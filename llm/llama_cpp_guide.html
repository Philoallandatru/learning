05 / INTERACTIVE CALCULATOR

KV Cache 的容量、精度与性能

对于标准全注意力架构，可估算：M(KV) ≈ Layers × Context × KV Heads × Head Dim × (K 字节/元素 + V 字节/元素)。特殊模型架构需单独处理。

实时 KV Cache 容量计算器

4.00 GiB

理论 K + V 数据大小；不含内存对齐、其他 Buffer、特殊层布局。

与 FP16 / FP16 相比

基线 4.00 GiB · 节省 0%

参数 / 组合机制注意
-ctk f16 -ctv f16常规精度基线容量较大
-ctk q8_0 -ctv q8_0K/V 量化降低内存观察内核兼容、质量
-ctk q4_0 -ctv q4_0进一步降低容量质量与数值敏感性风险
K/V 混合类型分别取舍 K 与 V需验证实际后端支持
--ctx-size / -c设置上下文预算增长会提高 KV 容量需求

文档中 K/V 还可选择 f32、bf16、q4_1、iq4_nl、q5_0、q5_1 等。不同后端与构建支持可能有差异；观察启动日志是否回退到其他内核。

模型权重 Q4 不等于 KV 自动 Q4；上下文设置 32K 也不意味着每个 1K 请求都执行完整 32K Attention。实际已使用长度和缓存布局很重要。

13 / WEIGHT COMPRESSION

常规推理不是“每 Token 从 SSD 读完整权重”。Slot Save/Restore 也不是实时 SSD KV Offloading。实验必须区分冷缓存/热缓存、DRAM 命中和真实 SSD 读取。

三个 SSD 实验

测试操作指标
Cold Load控制文件缓存状态后启动Load Time、SSD 读取字节
Warm Load保持系统缓存并重新启动Load Time、Page Cache 命中
RAM Pressure固定内存压力，重复推理Major Fault、IOPS、P99
KV Restore保存/恢复相同 Slot 状态保存耗时、恢复耗时、减少的 PP Token
